# Blender AEX parameter picker on macOS (#1660)

In a Blender compositor descriptor node, set **Transport mode** to **Render AEX (macOS)** and enter an AEX path relative to `AEXCOMPAT_PLUGIN_ROOT`. Click **Refresh AEX parameters**. The list shows enabled, visible integer, float, and angle parameters by name and slot. Select one row and click **Use selected parameter** to fill its slot and default value. Enter a new **Integer value** or **Decimal value**, choose Classic or SmartFX, and bake. Slot 0 still bakes plug-in defaults. Changing the plug-in path clears the displayed list and selected slot. Manual slot entry retains the legacy **Parameter value** control.

The bundled wrapper invokes the existing headless description once for refresh, validates the complete description, and returns a bounded scalar list. Manual discovery waits for completion without a deadline; an interactive bake still has its frame deadline. It reports the description and source/worker identities without using hash equality as a launch precondition. The bake path still re-describes the AEX and rejects a missing slot or out-of-range value. If the AEX bytes change after refresh, the bake records both identities and shows a refresh warning; it does not suppress a valid frame. The list stores only names, slots, exact decimal text for ranges/defaults, and hashes in the `.blend` file. It stores no absolute AEX path, binary content, or license information.

Blender 4.5.8 LTS smoke used license-free `OLMToonDilate.aex` (SHA-256 `c05db8c118029ff3216d3cae8e6423e2eb41ca8f56de2fb3668db81b9b8c32b3`). Refresh returned `Search Radius`, slot 1, float range 0–100, default 2. Selecting it and baking SmartFX at value 80 changed 1,296 RGBA8 bytes versus the default bake. The default image SHA-256 was `cc8e7869f4cb95428fbc592c22ca251200e76aa8c6a9f38a536d8dc9ac98587e`; the changed image SHA-256 was `0bcc07de1631aa0395013f35790f719bd754f61e4bb2847a86fdc2365d3d8d63`. The `.blend` reload preserved the packed images, name, slot, range, selected value, and SmartFX choice. `OLMColorKey.aex` also returned 167 named scalar entries and selected `Threshold` correctly. Behavioral checks preserved integer 16,777,217 and decimal 0.1, rejected malformed worker identity, and kept scene and node-group selections separate when tree and node names matched. Changing the source path cleared the list/slot, and stale selection was rejected. After Effects was not started. The local AEX, `.blend`, image, and smoke JSON are not committed.

To reproduce, set `AEXCOMPAT_PLUGIN_ROOT` to the directory containing that legally held AEX and run the existing `tools/blender_aexcompat_parameter_smoke.py` using the Release harness and guest worker as documented in `docs/BLENDER_AEX_SCALAR_BAKE_2026-09-30.md`. The picker presents one override at a time; a custom compositor node is still a descriptor and not a direct compositor executor.
