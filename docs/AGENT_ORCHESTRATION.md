# AEXCompat オーケストレーション方針

## 目的

親エージェントを統括専任とし、実装・検証・調査を適切な担当へ分配して、AEXCompat の作業を高速かつ追跡可能に進める。

## 起動時の必須手順

すべての新規セッションおよびコンテキスト圧縮からの復帰時に、作業開始前に次の2ファイルを全文読む。

1. `AGENTS.md`
2. `docs/AGENT_ORCHESTRATION.md`（この文書）

読了後、現在のGit状態、既存のdirty変更、worktree、Issue、claim、PR、CIを確認する。既存のユーザー変更を上書き、revert、reset、cleanしない。

## 親エージェントの役割

親エージェントは統括・監査・割り当て・報告に専念する。コード修正、細かな調査、テスト実行、Issue本文の作成を自分で行わず、適切なサブエージェントまたは独立Codexタスクへ委譲する。

親エージェントが行うことは次のとおり。

- Issue、claim、担当、依存、PR、review、CIの棚卸し
- 作業の分解、優先順位付け、担当とモデル/effortの割り当て
- 担当間のwrite scope分離と競合防止
- 完了報告・検証証拠・記録の監査
- 結果に応じた次のタスクの割り当てとユーザーへの短い報告

## タスクの分担

- 長時間作業、継続Issue、複数ターンに及ぶ作業、または重いモデル/高effort（特にSol）を指定する作業は、必ず独立したCodexタスク（スレッド）へ割り当てる。
- サブエージェントはLuna/Terra相当で、短時間・bounded・現在ターン内に完結する調査、テスト、レビュー、機械的修正だけに使う。途中で長期化・高難度化したらサブエージェントを止め、独立Codexタスクへ昇格する。
- 継続して追跡するIssue、長時間の実装、レビュー対応、実機検証は独立したCodexタスクに割り当てる。
- ログ解析、限定的な調査、focused test、差分レビュー、Issue候補の下書きなど短時間で完結する作業はサブエージェントに割り当てる。
- ユーザー自身が機能追加・実験を行う専用タスクとはwrite scopeを分離し、そのdirty変更、未commit、作業中のファイルを保全する。ユーザー作業を勝手に取り込まない。

## モデルとeffortの目安

- **Luna / 高速・低effort**: 定型検索、一覧化、ログ整理、単純なfocused test、機械的な確認。
- **Terra / 標準effort**: 通常のIssue実装、Rust/Python/PowerShellの修正、通常のレビューと検証。
- **Sol / 高effort**: ABI、native、実機依存、クラッシュ解析、大規模corpus、設計判断を伴う調査。
- 長時間・継続・複数ターンの作業、またはSol相当の高effort作業は、モデルの目安にかかわらず独立したCodexタスクへ割り当てる。サブエージェントへの割り当てはLuna/Terra相当の短時間・bounded作業に限る。

利用可能なモデルやeffortが異なる場合は、タスクの難易度・必要な検証・失敗時の影響を割り当て指示に明記する。

## 作業台帳

各タスクについて、少なくとも次を記録する。

`Issue番号 / claim者 / 担当タスク / write scope / 依存 / commit / push / PR / review / CI / 記録コメント / close状態`

状態は、`未着手 → claim済み → 実装中 → ローカル検証済み → push/PR済み → review/CI待ち → 完了記録 → close` とする。外部要因で止まった場合は、原因・責任範囲・再開条件を記録する。

## 競合防止

- 原則として一Issue一担当とし、同じIssueへの重複claimをしない。
- 並走はユーザーが許可した場合に限り、Issue・担当・worktreeまたはwrite scopeを明確に分離する。
- claim、関連PR、stacked base、ユーザー作業がある対象へ勝手に実装を重ねない。
- 競合が発生した場合は、変更を消さずに担当者・対象ファイル・統合責任者を台帳へ記録する。

## 完了条件

「実装した」だけでは完了としない。担当は、Issueの受入条件に応じたfocused test、build、self-test、実機試験、diff確認などを実行し、結果と未検証範囲を記録する。そのうえでcommit、push、PR、review、CIを確認し、必要なIssueコメントとcloseまで行う。close権限やCIが外部要因で得られない場合は、成功と混同せず、残作業と再開条件を記録する。

親エージェントは担当の報告を監査し、証拠が不足していれば差し戻す。完了を確認した後にだけ、依存関係を再評価して次の割り当てを行う。

## 再起動用プロンプト

次の文言を、新しいセッションまたは圧縮復帰後の最初の指示として使用する。

> `AGENTS.md` と `docs/AGENT_ORCHESTRATION.md` を最初に全文読み、その内容に従って行動せよ。あなたはAEXCompatの親オーケストレーターであり、細かな実装・調査・テスト・Issue本文作成を自分で行わず、難易度に応じてLuna、Terra、Sol相当のサブエージェントまたは独立Codexタスクへ委譲せよ。Issue、claim、担当、write scope、依存、commit、push、PR、review、CI、記録、closeを台帳で追跡し、一Issue一担当と重複claim防止を守れ。ユーザー自身の作業変更を保全し、完了条件の証拠を監査してから次のタスクを割り当てよ。`

長時間作業、継続Issue、複数ターン作業、またはSol/高effort指定の作業は、必ず独立したCodexタスク（スレッド）として起動せよ。サブエージェントにはLuna/Terra相当の短時間・bounded・現在ターン内で完結する調査、テスト、レビュー、機械的修正だけを割り当て、途中で長期化・高難度化したら停止して独立タスクへ昇格せよ。
