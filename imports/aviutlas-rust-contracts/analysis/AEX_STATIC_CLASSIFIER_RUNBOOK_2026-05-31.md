# AEX Static Classifier Runbook - 2026-05-31

Purpose: define Phase 0 classification for `.aex` files without executing
plug-in code.

This runbook is the next step after
`analysis/AE_AEX_AEP_STATIC_INVENTORY_2026-05-31.json` and before any sandbox
worker loads a plug-in.

## Safety Rules

- Do not call `LoadLibrary`.
- Do not use `libloading`.
- Do not start After Effects.
- Do not run `.aex` entry points.
- Do not copy `.aex` binaries into public fixtures.
- Do not hash private binaries unless the user explicitly asks for a local-only
  duplicate/integrity task.
- Treat classifier outputs as local-only metadata until reviewed.

## Tooling Ladder

Use the least invasive source first.

1. Inventory JSON:
   - no filesystem scan needed;
   - gives path/size and first inferred class.
2. Adjacent source:
   - `build.rs` generated by Rust/pipl projects often records PiPL metadata.
   - This is strong local evidence but still not proof of binary contents.
3. Resource/source files:
   - `.r`, `.rc`, or PiPL source files can identify AEGP vs AEEffect.
4. PE header/export tools:
   - read-only tools such as `dumpbin`, `llvm-readobj`, `llvm-objdump`, or
     Visual Studio tooling if available.
   - These may inspect PE headers/exports/resources but must not execute code.
5. Binary PiPL resource parser:
   - only after a parser is written/reviewed as read-only.
   - Parser output remains metadata-only.

## Class Inference

### Classic effect candidate

Evidence examples:

- adjacent `build.rs` has `Property::Kind(PIPLType::AEEffect)`;
- adjacent `build.rs` has `Property::CodeWin64X86("EffectMain")`;
- adjacent source uses `ae::define_effect!`;
- docs describe an AE effect plug-in;
- exported entrypoint appears to be effect-style.

Important nuance: incidental AEGP suite calls inside an effect project do not
make the plug-in an AEGP. PiPL/build metadata wins over incidental API usage.

### SmartFX-capable

Evidence examples:

- PiPL or adjacent source includes `SupportsSmartRender`;
- source handles `SmartPreRender`, `SmartRender`, or `SmartRenderGpu`.

Important: SmartFX-capable does not mean blocked. It means v0 image probe should
still attempt only the classic legacy path if present, and report SmartFX as
deferred.

### AEGP

Evidence examples:

- PiPL `Kind { AEGP }`;
- `EntryPointFunc`;
- command/menu registration;
- idle hook;
- PICA suite handler;
- named-pipe AE controller patterns.

AEGP is not a v0 image render fixture.

### Heavy/specialized

Evidence examples:

- ONNX/depth/flow model usage;
- particle/optical flare/generator semantics;
- large external dependencies;
- GPU-only or project-dependent behavior.

Defer until the sandbox and reporting pipeline are stable.

## Implemented Optional Inspection Slice - 2026-06-01

`aviutl-rs/examples/aex_static_classifier.rs` now has two explicit opt-in
inspection flags:

- `--inspect-pe` reads PE headers, export names, and resource directory type
  names plus bounded PiPL resource-entry metadata. It records resource
  id/name, language id/name, data size, and codepage with `contents_read=false`.
  It does not parse PiPL payload bytes, hash files, load modules, or execute
  plug-in code.
- `--inspect-pipl-payload` requires `--inspect-pe` and performs a bounded
  semantic-only PiPL content scan. It reads at most 16 KiB per PiPL resource
  and matches only already-expected strings from adjacent source/static
  metadata, such as display name, category, match name, and entrypoint. It does
  not emit raw bytes, unknown properties, hashes, decoded layouts, or parameter
  schemas.
- `--inspect-adjacent-source` reads adjacent `build.rs` text only and extracts
  PiPL declarations such as `PIPLType::AEEffect`, `Property::Name`,
  `Property::Category`, `Property::CodeWin64X86`, and
  `Property::AE_Effect_Match_Name`.
- Adjacent source evidence is applied only when the declared
  `Property::Name(...)` matches the `.aex` file stem after normalization; a
  mismatch remains evidence but does not promote the candidate.

The default classifier mode still does not open `.aex` binaries or adjacent
source files. The opt-in local run
`target/aex-static-classifier/catalog.pe-source.local.json` observed the
following metadata for the first fixture queue:

| Candidate | PE evidence | Adjacent source evidence | Status |
| --- | --- | --- | --- |
| `AdaptiveFilter` | `x86_64`, `PIPL` resource type/entry metadata, `EffectMain` export | `AEEffect`, `Filter`, `ONMK_AdaptiveFilter`, `EffectMain`, `SupportsSmartRender` | `candidate_for_contract_probe`, SmartFX deferred |
| `MedianPro` | `x86_64`, `PIPL` resource type/entry metadata, `EffectMain` export | `AEEffect`, `Filter`, `ONMK_MedianPro`, `EffectMain`, `SupportsSmartRender` | `candidate_for_contract_probe`, SmartFX deferred |

This strengthens fixture review evidence but does not approve loading,
describe, render, OFX routing, or PiPL payload parsing.

## Implemented Bounded PiPL Content Scan - 2026-06-01

The classifier now has a stricter opt-in scan:

```powershell
cargo run --example aex_static_classifier --no-default-features -- `
  --inspect-pe --inspect-adjacent-source --inspect-pipl-payload `
  --output target\aex-static-classifier\catalog.pe-source-pipl.local.json
```

The scan is intentionally not a general PiPL parser. It checks whether expected
semantic strings already known from adjacent source or static metadata are
present inside bounded PiPL resource contents. The report field
`pipl_content_scan` records:

- status such as `semantic_matches`, `partial_semantic_matches`, or
  `no_semantic_matches`;
- `scan_mode=bounded-expected-string-match-only`;
- byte limit and bytes read;
- matched whitelisted fields only;
- `contents_emitted=false`.

The local opt-in run observed:

- 40 local AEX rows with PiPL resource metadata;
- 30 `semantic_matches`;
- 7 `partial_semantic_matches`;
- 3 `no_semantic_matches`;
- no raw PiPL bytes, hashes, base64, image paths, worker paths, native load
  result, rendered pixels, decoded parameter schemas, or SDK layouts emitted.

This is useful evidence before `describe`, but it is still not parameter
discovery or native execution.

## Implementation Status - 2026-05-31

- `aviutl-rs/examples/aex_static_classifier.rs` implements the first
  metadata-only classifier slice. It reads the static inventory and emits a
